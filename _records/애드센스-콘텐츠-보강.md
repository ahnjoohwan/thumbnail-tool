## 변경점
- AdSense 정책 위반("게시자 콘텐츠가 없는 화면에 광고" + "가치가 별로 없는 콘텐츠")
  대응으로, 도구 UI 아래에 노출되는 가이드 콘텐츠 영역을 추가.
- 신규 `src/components/ContentSection.tsx` (서버 컴포넌트) — 제목/리드/본문 섹션/FAQ를
  구조화해 렌더. `P`, `UL` 헬퍼 export.
- 신규 `src/content/pages.tsx` — 홈/리사이즈/대량/썸네일 4개 페이지의 고유 한국어
  콘텐츠 데이터(사용법·채널별 규격·팁·FAQ). 온라인 셀러/쇼핑몰 운영자 타깃.
- `app/page.tsx`, `app/resize/page.tsx`, `app/bulk/page.tsx`, `app/thumbnail/page.tsx`:
  도구 클라이언트 컴포넌트 아래에 `<ContentSection>` 렌더. 각 page에 고유 `metadata`(title/description) 추가.
- `app/layout.tsx`: 루트 metadata를 셀러 대상 설명으로 보강, title template 적용.

## 이유·맥락
- 순수 도구(JS 웹앱) 사이트는 화면이 버튼/캔버스 위주라 "읽을 글"이 거의 없어
  AdSense의 최소 콘텐츠 요건에 자주 막힌다. 기존 각 page.tsx는 클라이언트 컴포넌트만
  렌더하는 5줄짜리였음.
- 도구는 `height: calc(100vh - 48px)`로 첫 화면을 채우므로, 콘텐츠는 그 아래
  스크롤 영역에 배치(도구 사용성 유지 + 크롤러가 읽는 초기 HTML에 텍스트 포함).
- 키워드 나열이 아니라 실제로 셀러에게 도움 되는 정보(채널별 이미지 규격, 화이트/그레이
  배경 선택 기준 등)로 작성해 "고유·우수한 사용자 환경" 기준을 함께 충족하도록 함.

## 영향 / 후속
- `next build` 통과, 4개 콘텐츠 페이지 모두 정적 프리렌더(○)로 텍스트가 초기 HTML에 포함.
- 후속: 배포(Vercel) → AdSense 콘솔에서 "문제를 수정했음" 체크 후 **검토 요청**.
  검토는 보통 수일~2주 소요.
- 홈(`/`)과 `/resize`는 같은 ResizeClient를 렌더하지만 콘텐츠는 다르게(홈=전체 개요,
  resize=리사이즈 가이드) 배치해 중복 콘텐츠를 피함.
