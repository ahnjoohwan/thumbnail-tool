## 변경점
- `src/components/AdSlot.tsx` 추가: `NEXT_PUBLIC_ADSENSE_CLIENT` / `NEXT_PUBLIC_ADSENSE_SLOT` 환경변수가
  모두 설정된 경우에만 애드센스 광고 단위를 렌더링 (없으면 `null` 반환).
- `src/app/layout.tsx`: `NEXT_PUBLIC_ADSENSE_CLIENT`가 설정된 경우에만 adsbygoogle 스크립트를 로드.
- `/resize`, `/bulk`, `/thumbnail` 각 화면의 다운로드 섹션 하단에 `<AdSlot />` 배치.
- `.env.example`에 두 환경변수 추가.

## 이유·맥락
- 현재 thumbnail-tool은 회사 내부 사용자용으로 운영 중.
- 동일 기능을 외부에 공개해 트래픽을 모으고 애드센스 수익화를 시도하려는 계획이 있음.
- 코드를 분리(fork)하지 않고, 같은 repo를 두 개의 Vercel 프로젝트(내부용/공개용)로 배포하면서
  공개용에만 환경변수로 광고를 켜는 방식(A안)을 선택.

## 영향 / 후속
- 내부용 배포: 환경변수 미설정 → 광고 없음 (기존과 동일).
- 공개용 배포(신규 Vercel 프로젝트 `thumbnail-tool-public.vercel.app`): `NEXT_PUBLIC_ADSENSE_CLIENT`, `NEXT_PUBLIC_ADSENSE_SLOT` 설정 필요.
  - 애드센스 대시보드에서 공개용 도메인을 사이트로 등록하고, 해당 사이트용 광고 단위(slot id)를 새로 발급받아야 함.
- 두 코드가 한 repo에서 갈라지지 않으므로, 기능 변경은 자동으로 양쪽에 반영됨. 단, 공개용에 랜딩/SEO
  요소가 많이 늘어나면 그때 별도 repo로 분리(B안) 검토.

## 후속 — 사이트 소유권 확인 트러블슈팅
- `src/app/page.tsx`가 `redirect("/resize")`였던 탓에 루트(`/`)가 Next의 `__next_error__` 셸을
  반환해 `<head>` 안에 스크립트 태그가 없었음 → `<ResizeClient />`를 직접 렌더링하도록 변경.
- `public/ads.txt` 추가 (ads.txt 스니펫 방식 fallback용).
- `next/script`의 `strategy="beforeInteractive"`는 `<link rel="preload">` + 인라인
  `__next_s` 등록 스크립트로 변환되어, 애드센스 크롤러가 찾는 리터럴
  `<script src="https://pagead2.../adsbygoogle.js?client=...">` 태그가 생성되지 않음
  → `next/script` 대신 평범한 `<script>` 태그로 교체.
- Vercel `--prod` 재배포 후 프로덕션 도메인(`thumbnail-tool-public.vercel.app`) alias가
  자동으로 최신 배포를 가리키지 않는 경우가 있어, 매 배포마다
  `vercel alias set <최신 배포 URL> thumbnail-tool-public.vercel.app` 재실행 필요.
