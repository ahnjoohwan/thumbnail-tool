## 변경점
- 세 다운로드 핸들러(thumbnail / resize / bulk)의 `handleDownload`를 리팩터링.
- 기존: 항상 `JSZip`으로 모든 결과물을 압축 → `.zip` 다운로드.
- 변경: 생성된 blob을 `files[]` 배열에 먼저 모은 뒤 분기.
  - `files.length === 1` → 압축 없이 해당 이미지 blob을 그대로 개별 다운로드 (파일명은 원래 파일명 사용, thumbnail은 하위폴더 경로 제거 후 leaf 파일명).
  - `files.length > 1` → 기존대로 ZIP 생성 후 다운로드.
- 버튼 라벨 조정: bulk는 `items.length === 1`이면 "다운로드 (1개)", 아니면 "ZIP 다운로드 (N개)". 진행 중 문구는 세 곳 모두 "압축 중…" → "처리 중…"으로 통일(단일 다운로드 시 "압축"이 어색).

## 이유·맥락
- 경우에 따라 작업본이 1개만 생기는데, 이때 ZIP으로 감싸면 사용자가 압축을 풀어야 하는 불필요한 단계가 생김.
- 요청: "1개인 경우에는 압축 다운로드가 아니라 그냥 개별로 다운되게".

## 영향 / 후속
- 결과물 2개 이상은 기존 ZIP 동작 그대로 유지.
- thumbnail의 경우 배경 여러 개 선택 시 하위폴더(`{bgKey}/`) 경로가 붙는데, 이 케이스는 파일이 2개 이상이라 ZIP 경로로 감. 단일 다운로드에선 `split("/").pop()`으로 leaf 파일명만 사용.
- `npx tsc --noEmit` 통과.
